## 新增需求

### 需求:命令行参数配置

系统必须支持通过命令行参数配置监听 IP 和端口，默认值为 `192.168.1.100:8890`。参数必须包含 `--ip`、`--port`、`--mode`，以及 `--output`（pcap 模式必需）。

#### 场景:默认参数运行
- **当** 用户不带参数运行程序
- **那么** 系统使用默认 IP `192.168.1.100` 和端口 `8890`，模式为 `console`

#### 场景:自定义 IP 和端口
- **当** 用户指定 `--ip 192.168.1.200 --port 8891`
- **那么** 系统监听 `192.168.1.200:8891`

#### 场景:pcap 模式指定输出文件
- **当** 用户指定 `--mode pcap --output capture.pcap`
- **那么** 系统将报文写入 `capture.pcap` 文件

### 需求:控制台展示模式

系统必须在 `console` 模式下实时打印捕获的 UDP 报文信息，包括时间戳、源地址、目的地址、长度和 Payload 预览。

#### 场景:成功捕获 UDP 报文
- **当** 收到 UDP 报文
- **那么** 系统在控制台打印 `[时间戳] SRC_IP:SRC_PORT -> DST_IP:DST_PORT | 长度 | Payload预览`

#### 场景:无 Payload 的 UDP 报文
- **当** 收到 UDP 报文且 Payload 为空
- **那么** 系统仍打印报文头信息，Payload 预览显示为空

### 需求:pcap 文件写入模式

系统在 `pcap` 模式下必须将每个捕获的 UDP 报文追加写入指定的 pcap 文件。文件必须能被 Wireshark 正确打开和回放。

#### 场景:pcap 文件创建
- **当** 用户指定 `--mode pcap --output capture.pcap` 运行程序
- **那么** 系统创建 `capture.pcap` 文件（若不存在），并写入有效的 pcap 文件头

#### 场景:pcap 追加写入
- **当** 程序正在运行且已收到多个 UDP 报文
- **那么** 每个报文都被追加写入 pcap 文件

#### 场景:Wireshark 兼容性
- **当** pcap 文件已写入多个报文
- **那么** 该文件必须能被 Wireshark 正常打开，显示所有捕获的 UDP 报文

### 需求:持续监听

系统必须持续监听指定端口，直到用户按 Ctrl+C 终止程序。

#### 场景:持续接收报文
- **当** 程序已启动监听
- **那么** 系统持续接收并处理发往指定端口的 UDP 报文

#### 场景:平滑终止
- **当** 用户按 Ctrl+C
- **那么** 系统优雅退出，关闭文件句柄，打印统计信息（捕获报文数量）
